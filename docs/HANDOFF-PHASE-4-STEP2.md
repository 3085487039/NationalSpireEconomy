## 6. 第一步定下的对外行为（第二步必须保持）

1. **标记协议只由 S 段教模型**：`[Trade: 赞助, Amount: 金额, Direction: npcToPlayer]`、`[Deal: accept]`
   —— 这段文字在 `config/ai_prompt_economy.json` 的 `stableBlockSuffix` 里，**必须零数字**（否则模组拒绝启用）。
2. **意图补全**：标记显式 `Direction` 优先，其次 `economy_config.json` 的 `trade.kindDirections`；**都没配到就拒绝**（绝不猜钱的方向）。
3. **回声守卫**：模型回复里若逐字引用了**玩家本轮说过的话**里的标记 ⇒ 不算 NPC 提议/同意（真机曾出现"这行字你从哪抄来的"）。
4. **两票 = 两个收据键**（`confirm:…:npc|player`），幂等由收据本天然保证；`Status` 是只读投影。
5. **弹窗**：主线程 + `NModalContainer.Instance != null` + `OpenModal == null` 才弹；任何一步不满足只写日志并退化为聊天指令（玩家在私信里回 `确认 <单号>`）。
6. **预览文案含金额**，因此只能进 **V 段**或日志，**绝不能进 S 段**。

    校验被拒时**没有预览也没有弹窗**（日志里是 `交易标记未落单（原因）`）。
    所以"没看到弹窗"先翻这一行，别先怀疑弹窗/Rendering（21:30 已经证明它能弹）。
27. **★"动钱"必须是一次可辨认、可回退的动作（23:0x 定下的做法）**：结算的开关不是写死的 `const`，
    而是 `TradeConfirmationGate.SettlementWired` + 环境变量 `NSE_SETTLEMENT=1`。
    理由有两条：① `const false` 会让所有结算分支变成不可达代码（CS0162），而本项目零警告是硬指标；
    ② 真机验钱要能"带开关跑一次、不带开关就恢复不动钱"，不该要求每次重新编译。
    **默认关，且 `SettlementIsDeliberatelyNotWired` 这条测试钉住默认值。**
28. **钱动了而状态没写盘 = 可以再动一次**：结算之后必须 `force:true` 落盘（`SaveQuietly`），
    审计要先写（审计是旁路，落盘失败时它仍是证据）。反过来，**待确认单也要落盘**——
    否则重启后单号失效，玩家拿着旧号来确认只会得到一句"找不到交易单"（真机栽过）。
29. **`Transfer` 的失败必须"不留痕"才能安全重试**：`Move` 会把整笔的幂等键登记掉，
    而回滚不会撤销它——于是"收了又退回去"会被幂等闸吞掉，重放返回 `AlreadyApplied` 而账上一分未动。
    **修法：回滚时释放整笔键与 `rollback:` 键**（`ReceiptBook.Unmark`），失败的尝试作废、可安全重试。
30. **异常路径也要能看见**：玩家腿失败时，`Transfer` 的对外说明原先只写"玩家侧失败，已回滚"，
    把钱包给的真实原因（"尚未导入"）盖住了。**动钱路径上的失败原因必须一路带到日志**，
    否则排障只能靠猜。
31. **★ 动钱开关不能用环境变量做主路径（23:2x 实测）**：玩家是用 **Steam 启动**游戏的，
    而 Steam 启动的游戏**继承的是 Steam 客户端的进程环境**，我们临时 `$env:NSE_SETTLEMENT=1` 根本传不进去；
    想绕过 Steam 直接跑 `SlayTheSpire2.exe` 又会被 Steamworks 挡下——实测弹窗
    「**Steam初始化失败。请确保您是从 Steam 客户端启动游戏的**」（往游戏根目录放 `steam_appid.txt` 填 `2868840`
    也救不了，那只是 dev 模式的补救，仍要求 Steam 客户端在正确的上下文里）。
    **结论：开关做成配置项 `economy_config.json → trade.settlementWired`**（改一行 + 重启，Steam 启动照样生效），
    环境变量只作为"命令行启动时"的便捷补充。
32. **沙箱内的 `Get-Process` 看不到用户的游戏进程**（23:2x 实测）：脚本的"游戏是否在运行"守卫因此在
    "放行/拦下"之间抖（沙箱内查无进程、授权视角下有两个 `SlayTheSpire2`）。
    **换版的正确判据是"目标文件能否独占写"**，不是"有没有同名进程"；
    另外**沙箱杀不掉用户的进程**（`Stop-Process` → `Access is denied`），残留进程只能由人来关。
33. **启动失败也会留下占内存的残留进程**：那两次失败的启动各留了一个 650MB+ 的 `SlayTheSpire2`
    卡在报错弹窗上。它们**没有加载模组**（日志最后写入仍是上一次），所以不持有 DLL、不影响换版，
    但会让人误判"游戏在跑"。**换版前先看一眼"目标文件是否可独占写"。**
34. **★ 工具给的标识必须是"人在界面上能看到的那个"（23:4x）**：`pick-sponsor.py` 原先只打印
    PersonId（`crowd-5-4`），而游戏里显示的是**人名**（「酸橙汽水」）——于是连续三轮都是
    "随手找个私信窗口里的人要 $500"，而随手挑到的人余额都在 $6.5k~8.3k，$500 必然被情绪闸拒。
    **修法**：工具去原版生涯存档（只读）里按 `WorldId` 找到当前这一局，把 id 映射成 `Name`。
    注意**当前这局的生涯档文件名带哈希**（`national_spire_career-<hash>.json`），无后缀那份是另一局。
35. **★ 甲方的"范围决策"必须落成代码闸门，不能只写在文档里（23:5x 自查发现）**：
    甲方拍板"首笔只开通 NPC→玩家"，而我在实现结算器时**没有给方向加闸**——开关一打开，
    反向（`playerToNpc`，例如「雇佣」）只要双方确认就会照常结算，**玩家的影子余额会被扣**，
    恰好违反那条决策。**修法**：`TradeSettlement` 前置闸门里加方向判定，反向返回
    `DirectionNotWired` 并写明原因，**一分钱不动**（回归测试 `PlayerToNpcDirectionIsNotWiredYet`）。
    **教训**：凡是“阶段范围/开关”的拍板，都要在代码里找到那个"不许过"的判定点，否则它只是一句愿望。

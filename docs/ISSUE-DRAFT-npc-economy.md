## 正文

你好，先感谢你做的 NationalSpire，社区与生涯的完成度是我见过最高的。

我在你的模组基础上写了一个**独立的二开模组**，做的是一件上游目前没有的事：
**让 NPC 有自己的钱**。跑通之后想按你说的走 PR，但这中间有个结构问题必须先跟你对齐，
所以先开这个 Issue 谈设计，不直接提 PR。

### 一、先说结论：我想补的是哪一块

我核对过上游源码，确认边界是这样（如果哪里理解错了请直接说）：

| | 上游现状 | 出处 |
| --- | --- | --- |
| 玩家经济 | 完整：`Credits` / `CreditFraction` / `Ledger`、商城、股票外汇 K 线 | `CareerData.cs:66`、`LifeData.cs:7`、`EconomicActions.cs` |
| 赞助合同 | 有，但 `Retainer` / `WinBonus` 是**品牌付给选手**的数额 | `EsportsData.cs:135` |
| **NPC 个人资产** | **没有** —— `CareerPerson` 里一个金额字段都没有（只有 `Fans` / `Rating` / `ClubId` / 性格 / 好感） | `CareerData.cs`（`class CareerPerson`） |

**所以我想加的不是"经济系统"（你已经有），而是"NPC 侧的账户"**：
每个 NPC 有自己的余额、工资、赛季收入，并且**玩家和 NPC 之间能真的转账**。
玩家的钱仍然是原版那位（我不碰 `Credits` 的语义），NPC 的钱是新增的一层。

> ⚠ 这里想先确认一件事：**你说的"需要经济系统"，指的是不是这个方向？**
> 如果你指的是别的（比如把玩家侧做得更深），那我这套可能要重新定位，
> 先问清楚比我先写代码好。

### 二、⚠ 必须先谈的结构问题（这也是我没直接提 PR 的原因）

我的模组是一个**独立仓库**，与上游**没有任何共同祖先**：
上游是 466 个 `.cs` 平铺在根，我是 `src/` + `tests/` + `docs/` 的独立结构。

**后果**：如果我把自己的分支 PR 过来，Git 会认为我要**用我的项目替换掉你的整个项目** ——
那不是提功能，是把你的代码删掉。我实际试过一次，PR 提交不上去，原因就是这个（不是网络或凭据）。

所以想问你要哪种形态：

| 方案 | 说明 | 我的成本 |
| --- | --- | --- |
| **A. 你收编，我按你的结构重写** | 我把它改写成上游的平铺结构与模块规范，分几个 PR 提 | 高（工程量最大） |
| **B. 作为上游的一个子模块/目录并入** | 保留相对独立的 `Economy/` 目录，通过你定义的接口接线 | 中 |
| **C. 你只要设计，实现你自己来** | 我把设计与踩过的坑写清楚，代码不并 | 低 |
| **D. 维持独立** | 玩家两个都装 | 无 |

**我倾向 A 或 B，你说了算。** 如果选 A，我建议**先只谈一个最小 PR 的范围**（见第四节）。

### 三、我这个实现里，有哪些是"真机踩出来的"、可能对你有用的结论

这几条是我花了不少代价才确认的，无论最后并还是不并，应该都对你有用：

1. **补丁"挂载成功"≠"会命中"**。Harmony 挂上方法没有异常、没有日志，
   但游戏根本不走那条路 —— 我在这上面栽过三次。后来我改成用探针记录
   **方法入口 + 调用栈**才算有证据（含"这个类型在加载器下有几份副本"）。
   > 如果你的模组也有外部补丁点，这条可能值得参考。
2. **"注入进 Prompt" ≠ "玩家能看见"**。我一度以为把内容写进提示词玩家就看到，
   实际它只进了模型上下文。要让玩家看见必须走 UI 通道。
3. **给 AI 看的经济口径必须防它撒谎**。模型会说"钱已经转过去了"而账本没动，
   所以我在注入里明确写了"只有标着『已结算』的才算真的动过"，
   并且**钱只有在双方确认 + 四道闸都过的情况下才动**。

> 如果你的模组里已经有类似结论，那当我没说；如果这几条对你有新信息，我可以把细节整理给你。

### 四、如果走 A/B，我建议的最小第一步

你的 CONTRIBUTING 写的是"一个 PR 一个目的"，所以我**不建议**一次把整个经济系统并进来。
按侵入性从低到高，我建议的第一刀是：

**「只读成交预览 + 双人确认」** —— 也就是"这笔交易会发生什么"的展示层：

- **完全不动原版**：不写存档、不改数值、不碰 `Credits`
- 玩家能看到：这笔交易双方余额怎么变、几条校验各自说了什么、有效期到哪天
- **价值可以独立成立**：它本身就提升了透明度，不依赖后面的动钱部分

如果这一步你觉得方向对，再谈后面的（真正动钱、玩家发起交易、审计落盘）。

### 六、我的实现目前**没做到**什么（先说清楚）

我不想让你按"它什么都有"的预期来评估，所以把已知短板列在这里：

| # | 短板 | 现状 | 影响 |
| --- | --- | --- | --- |
| 1 | **多人（合作）模式完全没处理** | 只在**单人**下跑过。你的 `EconomicActions` 有 `CoopJson.Copy` + 回滚那一套，我这套没有对应机制 | 多人下可能账目分叉或丢失 —— 这一项**必须**听你的意见 |

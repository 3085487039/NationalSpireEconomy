# 文档索引（docs/）

这里是 NationalSpireEconomy 的**全部交接与设计记录**。
它们不是"介绍材料"，而是这个项目的**主要资产**：每一份都记着哪条路走不通、为什么走不通、
以及当时的真机证据（日志行、存档键、审计行、DLL 哈希）。

> **接手请从 `HANDOFF-PHASE-5-REVIEW-AND-PLAYER-TRADE.md` 开始**（最新一段：审查修复 + 玩家发起交易）。
> **只想先读一遍全貌，看 [`PROJECT-SUMMARY.md`](PROJECT-SUMMARY.md)。**
>
> 文档里出现的历史路径（例如"顶层 `HANDOFF.md`"）在仓库整理时统一改成了
> `docs/…`；实验数据、哈希与代码行号**一律保持当时实测的原值**，未做任何改写。

## 读这些文档的正确姿势

这个项目的文档密度很高，而且**大量内容是"反直觉结论 + 证据"**。三个建议：

1. **"坑位"章节优先读。** 每份交接文档末尾那些编号条目，是拿真机失败换来的，
   通常一句话就能省掉你半天（例："V 段不面向 UI"、"打完包别再跑零依赖基线"、
   "模板里不能出现标记文本"）。
2. **不要只信结论，去看证据。** 每条结论都附了日志行/哈希/行号；
   如果代码已经变了，**以代码为准**，并顺手更新文档。
3. **动钱相关的一切都先在文档里搜一遍。** 搜索关键词：
   `EconomyLedger`、`幂等`、`SettlementWired`、`方向闸`、`落盘`、`LastTrade`。

## 文档约定

- 文档里写的数量（零依赖 / 含游戏引用基线）是**当时**的实测值，
  会随功能增加而变；以 `CONTRIBUTING.md` 里记录的当前值为准。
- 所有哈希都是 SHA256，前 8 位用于口头引用，全文用于核对。
- 沙箱/环境相关的约定（dotnet 家目录、NuGet 出网受限、什么操作做不到）
  集中写在 [`HANDOFF-PHASE-4-STEP5.md`](HANDOFF-PHASE-4-STEP5.md) §1.5。

## 3. 第一步：真机验收（**现在做**）

**目标**：拿到"钱真的动了"的证据。

**照着做**：`docs/CHECKLIST-REAL-MACHINE-VERIFICATION.md`（含开关命令、录制要点、三处证据、判据表、关回步骤）。

**产出**：30–60 秒 GIF + `LastTrade` + 审计行 + `mod-debug.log` 关键行。

**为什么先做这个**：
- 标题写"已有可运行实现"就必须有证据，否则会被读成"想让你做"
- 没有真机证据，Issue 里谈什么都虚

**风险**：低。开关临时打开、验完关回；不碰原版存档（只读）。

---

## 4. 第二步：精简材料

作者 CONTRIBUTING 第一句是"**动手之前先聊设计意图**"。

| 材料 | 怎么处理 |
| --- | --- |
| `PROJECT-SUMMARY.md`（约 300 行） | **精简成 1 页**。他要点是设计意图，不是实现细节 |
| 踩坑结论（挂载/注入/防撒谎） | **单独抽出**，当"对你有用的经验"送出去 —— 这是平等交流的筹码 |
| GIF | 放最前面 |
| 三处证据 | 按他 CONTRIBUTING §6 的格式贴 |

⚠ **不要把长文档直接甩过去。** 他不会读。

---

## 5. 第三步：开 Issue（**关键分岔点**）

**初稿已写好**：`docs/ISSUE-DRAFT-npc-economy.md`（发前先按里面的自检清单过一遍）。

**这封 Issue 要解决四件事**：

1. **确认方向** —— 反问"你说的需要经济系统是不是 NPC 侧这个方向？"（理解错了后面全白谈）
2. **摊开结构现实** —— 零共同祖先，问他要哪种形态（A 重写 / B 子模块 / C 只要设计 / D 独立）
3. **主动缩小范围** —— 建议第一个 PR 只做"只读成交预览 + 双人确认"（**完全不动原版**）
4. **问清 5 个设计问题** —— 钱存哪、钱从哪来、多人怎么办、旧存档怎么办、要不要动他的 UI

**姿态**：**平等讨论**，不是求职也不是求批准。你手上有他缺的东西（NPC 侧经济是真空缺）。

---

## 6. 第四步（分岔）

### 4A：他说要 → 拆 PR

**按"对上游的侵入性"从低到高排**（这也是建议的 PR 顺序）：

| 顺序 | 模块 | 侵入性 | 触发他"必须先确认"的红线吗 |
| --- | --- | --- | --- |
| **1** | **只读成交预览 + 双人确认** | **低**（纯读、不动原版） | ❌ 不触发 → **最好的敲门砖** |
| 2 | NPC 账户 + 工资/赛季结算 | 中（动存档 schema） | ✅ **要确认**（改数值/存档） |
| 3 | 玩家发起交易（形态 b） | 中（动交互生效方式） | ✅ **要确认** |
| 4 | 真正动钱 + 审计落盘 | 高（动存档） | ✅ **要确认** |
| — | NPC↔NPC | — | **明确搁置**（D3 已拍板） |

**每拆一个 PR，都要**：
- 同 PR 更新接口文档（他 CONTRIBUTING 的硬要求）
- 附两套基线数量 + 真机证据
- 一个 PR 一个目的

### 4B：他说不要 / 要换方向

**维持独立 mod，但这次沟通没白费**：
- 你确认了"NPC 侧经济"是他认知里的空缺（或不是）
- 你拿到了他对**数值口径、多人、旧存档**的意见 —— 这些对独立 mod 同样有用
- 关系建立了，以后还能再谈

## 9. 纪律清单（别踩）

1. **改开关必须重启游戏**（启动日志会明说 `★结算已接线`）
2. **验完**把开关关回 `false`（线上那份不在 git 里，只能靠你自己记得）
3. **验收完不要重打包**（会把 `bin` 覆盖成缩减版，破坏"三处一致"）
4. **不要在验收中途换版**（一次真机会话只对应一个 DLL 哈希，否则日志对不上账）
5. **不要引导 NPC 输出标记**（实测 NPC 会识破并回绝）
6. **正文证据优先于录像** —— 录像只能看，文本可核对
